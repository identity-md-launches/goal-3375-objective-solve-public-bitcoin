# Offline secp256k1 ECDSA verification benchmark

Run from the repository root.

```sh
python3 -I -B public-verify-bench/check.py
```

The check requires Python 3.8+ with the standard library, a C99 compiler with
shared-library support, POSIX shell tools and GNU `sha256sum`. It uses the
sibling `secp-oracle` vendored sources and builds a temporary library offline.
It runs the ten baseline test methods and three additional regression methods.
The generator-order test uses an unreduced, left-to-right multiply driven by
point addition, with neighbor checks at `N-1` and `N+1`.

## Sources and fixtures

- The baseline is the CC0-1.0 public synthetic corpus generated by
  `gen_fixtures.py`. Its 128 messages, keys and signatures retain SHA-256
  `b2a93674959ab6938447134b8738aff8385b3d4e3a9d9c10637e5826c7210812`.
  The native oracle independently regenerates the public points and low-S
  signatures, then verifies the baseline signatures. It uses Bitcoin Core
  libsecp256k1 v0.6.0, commit `0cdc758a56360bf58a851fe91085a327ec97685a`,
  with the existing per-file hash verification.
  [Baseline license](fixtures/LICENSE) · [Oracle provenance and MIT license](../secp-oracle/README.md)
- The six nonce answers are from `test_SECP256k1` through
  `test_SECP256k1_6` in python-ecdsa commit
  `71e3fc7240cf31584fb0e10bd58e2830f2fc5afc`. The source file SHA-256 is
  `db3a167d1ff102a6a028e147549b7875365969cbb5cd3e09c571ff1c9500056f`.
  The subset reformats published scalars, messages and expected nonces as hex.
  RFC 6979 specifies the procedure. The secp256k1 answers are supplied by the
  published test suite. [Pinned source](https://github.com/tlsfuzzer/python-ecdsa/blob/71e3fc7240cf31584fb0e10bd58e2830f2fc5afc/src/ecdsa/test_pyecdsa.py#L1950) · [MIT license](fixtures/rfc6979.LICENSE)
- The 23 Wycheproof cases are from C2SP commit
  `65ca494727a52944c204441c860b039e6786b99b`. The source JSON SHA-256 is
  `43db761c0a2eae71fb0755d355d5130e28ce64a5b07846cf27e7072082597a81`.
  The subset preserves selected test rows and their uncompressed public keys.
  The harness enforces short-form canonical DER for these signatures before
  invoking the raw-integer verifier. It also checks malformed SEC1 encodings
  and wrong messages, scalars and points. Valid high-S signatures follow the
  raw verifier's ECDSA semantics. The native oracle uses libsecp256k1's low-S
  policy for its own checks.
  [Pinned source](https://github.com/C2SP/wycheproof/blob/65ca494727a52944c204441c860b039e6786b99b/testvectors_v1/ecdsa_secp256k1_sha256_test.json) · [Apache-2.0 license](fixtures/wycheproof.LICENSE)

The acceptance check verifies the SHA-256 of each retained data file before running tests.

## Measurement

The check loads and decodes the 128 baseline vectors once for the benchmark,
runs the correctness gate, measures untraced verification throughput, then
repeats the verification workload under `tracemalloc` for peak Python
allocation. It reports elapsed seconds for each phase. The process peak RSS
is a lifetime high-water mark in KiB for the Python process. It excludes the
native compiler and oracle subprocesses.

Affine point addition uses a fixed distinct-point pair (`G + 2G`) and reports
additions per second separately from ECDSA verifications per second. Both rates
describe their specific synthetic workloads. A production search rate would
require a separate search benchmark.

For standalone benchmark runs, use the default 128 vectors and five repeats,
or reduce the workload.

```sh
python3 -B public-verify-bench/benchmark.py --repeat 5
python3 -B public-verify-bench/benchmark.py --limit 16 --repeat 2
(cd public-verify-bench && python3 -B -m unittest -v)
```
